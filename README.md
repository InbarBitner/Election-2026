# בחירות 2026 — פלטפורמת נתונים למערכת הבחירות לכנסת

אפליקציית ווב בעברית (RTL) סביב הבחירות לכנסת באוקטובר 2026: אגרגטור סקרים עם
ממוצע נע, אינדקס מפלגות, פיצ׳ר "רנטגן מועמד", צינור ETL, מנוע המלצות למצביע
וסקירת בחירות יומית אוטומטית.

> **נתוני הדגמה** — ראו [מה אמיתי ומה לא](#מה-אמיתי-ומה-לא). הסקרים המגיעים עם
> הפרויקט הם נתוני הדגמה מסומנים ולא מידע אמיתי, עד להרצת ה-ETL; המפלגות
> והיו״רים אמיתיים ומתועדים; המועמדים נטענים מהרשימות הרשמיות שאישרה ועדת
> הבחירות המרכזית.

## הרצה מהירה

```bash
# 1. תלויות
npm install --prefix web
pip3 install -r requirements.txt

# 2. מסד נתונים
cp .env.example web/.env
npm run db:push --prefix web

# 3. נתוני הדגמה + וקטורי מפלגות + סקירה יומית
python3 -m pipeline.seed
python3 -m pipeline.ml.build_vectors
python3 -m pipeline.brief.generate --date today --no-llm

# 4. הרצה
npm run dev --prefix web        # http://localhost:3000
```

> הפקודות כתובות `python3`/`pip3` בכוונה: ב-macOS אין `python` בלי הספרה,
> ופקודה שנכתבת בלעדיה נכשלת ב-`command not found` — כולל השלבים שכותבים
> למסד, כך שהאתר ימשיך להציג נתונים ישנים בלי שום הודעת שגיאה גלויה.

**שינוי ב-`data/seed/` נכנס לאתר רק אחרי הרצה חוזרת של שלב 3.** `git pull`
מעדכן את קבצי ה-JSON; מי שכותב אותם למסד הוא ה-seed, וללא הרצה חוזרת שלו האתר
יציג את הרוסטר הקודם. נתוני ההדגמה מוחלפים ולא מצטברים, כך שאין סכנת כפילויות.

ה-seed בטוח להרצה גם על מסד שה-ETL כבר מילא. הוא מעדכן את המפלגות במקומן במקום
למחוק ולטעון מחדש. מחיקה הייתה מתפשטת לתוצאות הסקרים ולמועמדים, שתלויים במפלגות.
הוא גם טוען נתוני הדגמה רק במקום שאין נתונים אמיתיים: לא סקרי הדגמה כשיש סקרים
אמיתיים, ולא מועמדים בדיוניים למפלגה שיש לה רשימה רשמית. מפלגה שהוסרה מקובץ
המפלגות נמחקת, יחד עם כל מה שהיה שייך לה.

## ארכיטקטורה

עיקרון מנחה אחד: **Python הוא offline/batch בלבד ו-Next.js הוא ה-runtime היחיד.**
צינור הנתונים כותב ל-Data Warehouse; האתר קורא ממנו. אין שירות Python חי
בפרודקשן, ואין לוגיקה עסקית שקיימת פעמיים בשתי שפות.

```
                 ┌───────────────┐
  מקורות ────────►   pipeline/   ├──────► Data Warehouse ──────► web/ (Next.js)
  (כנסת, סקרים,  │  extract →    │        (Prisma schema)        SSR + API routes
   פידי RSS)     │  transform →  │
                 │  load         │
                 └───────────────┘
```

| תיקייה | תפקיד |
|---|---|
| `web/` | Next.js 15 (App Router, TypeScript), Prisma, Recharts |
| `web/lib/` | הלוגיקה המספרית: `pollAverage.ts`, `seats.ts`, `cosine.ts` |
| `pipeline/etl/` | extract → transform → load |
| `pipeline/ml/` | בניית וקטורי עמדות למפלגות |
| `pipeline/brief/` | זיהוי אירועים וניסוח הסקירה היומית |
| `data/seed/` | נתוני ההדגמה ומאגר השאלון |
| `data/sources/` | הגדרת מקורות חיים (ראו [מקורות חיים](#הפעלת-מקורות-אמיתיים)) |

**סכמת הנתונים** ב-`web/prisma/schema.prisma` היא מקור האמת היחיד. Python לא
מגדיר אותה מחדש — הוא משקף (reflect) את הטבלאות בזמן ריצה, כך שהוספת עמודה
דורשת שינוי בקובץ אחד בלבד ו-`prisma db push`.

**מעבר ל-Postgres בענן** הוא החלפת `provider` ו-`DATABASE_URL`. הסכמה נכתבה
נייטרלית לספק בכוונה: בלי enums, בלי מערכים, בלי טיפוסים ייחודיים למנוע.

## חטיבה 1 — ליבת הפלטפורמה

### אגרגטור סקרים

במסד נשמרים רק **הסקרים הגולמיים**. הממוצע מחושב בזמן בקשה
ב-[`web/lib/pollAverage.ts`](web/lib/pollAverage.ts), כדי שהמשתמש יוכל לשנות את
חלון הממוצע (7 / 14 / 30 ימים) בלי הרצה מחדש של הצינור:

- משקל כל סקר = `√(גודל מדגם)` × דעיכה אקספוננציאלית לפי גיל (מחצית משקל אחרי שבוע).
- **סקר אחד לכל בית סקרים ליום.** בלי זה, בית סקרים שמפרסם מדי יום שולט בממוצע
  מכוח תדירות הפרסום בלבד — טעות מוכרת באגרגציה של סקרים.
- מפלגה שנעדרת מסקר נספרת כאפס מנדטים, לא מושמטת: היעדרות היא מידע.
- רצועת אי-ודאות = סטיית תקן משוקללת בתוך החלון.

[`web/lib/seats.ts`](web/lib/seats.ts) ממיר ממוצע מנדטים להקצאה בפועל: אחוז
חסימה 3.25% על נתח הקולות המשתמע, ואז **שיטת בדר-עופר** (מכסה שלמה ואז חלוקת
העודפים לפי `קולות/(מושבים+1)`) על 120 המושבים.

**הסכמי עודפים** נכללים בתחזית בכל מקום — דף הסקרים, בונה הקואליציות והסקירה היומית.
הם נטענים מ-[`data/seed/surplus_agreements.json`](data/seed/surplus_agreements.json),
עם מקור לכל הסכם, וחלים רק כששתי הרשימות עוברות את אחוז החסימה. דף הסקרים מציג
אילו מנדטים ההסכמים מזיזים לעומת חלוקה בלעדיהם.

### בונה קואליציות

`/coalitions` מאפשר לסמן כל מפלגה כ"בפנים", "בחוץ" או "פתוח", ומחשב כמה מנדטים יש
לבחירה ואילו צירופים **מינימליים** של המפלגות הפתוחות משלימים אותה ל-61 — כאלה שבהם
כל מפלגה נחוצה ([`web/lib/coalitions.ts`](web/lib/coalitions.ts)). הדף לא שופט אם
מפלגות ישבו יחד; זו החלטה של הקורא.

לצד המנדטים מוצג **הסיכוי** להגיע לרוב, מסימולציית מונטה קרלו של 10,000 בחירות
מדומות ([`web/lib/coalitionSim.ts`](web/lib/coalitionSim.ts)). בכל אחת המנדטים של
כל מפלגה מוגרלים סביב הממוצע, ועוברים את אותה חלוקה של `seats.ts`. שלוש הנחות,
שנבחרו ב-`research/09_coalition_montecarlo.ipynb`:

- **פיזור** — סטיית התקן של הסקרים מ-14 הימים האחרונים סביב הממוצע, **אחרי** הסרת
  ה-house effect של כל בית סקרים (בלי זה, הנטייה הקבועה של ערוץ 14 לליכוד נראתה
  כאי-ודאות של ±3.8 מנדטים במקום ±1.1).
- **רצפה של מנדט** — אף מפלגה לא נחשבת ודאית יותר מזה. למפלגות שעל סף אחוז החסימה
  זה קובע במידה רבה את הסיכוי לעבור.
- **מתאם 0.5 בתוך גוש** — טעויות סקרים נוטות לזוז יחד במחנה אחד. זו הנחה, לא מדידה.

ההגרלה נזרעת בערך קבוע, כך שהסיכויים משתנים רק כשהסקרים משתנים, לא בכל רענון.

### רנטגן מועמד

כפתור על כל מועמד פותח דיאלוג עם ארבע לשוניות — היסטוריית הצבעות (כולל אחוז
נוכחות, פילוח לפי נושא וסימון הצבעות נגד קו הסיעה), הצעות חוק, התבטאויות
וקשרים פוליטיים. הנתונים נטענים בעצלתיים מ-`/api/candidates/[id]/xray`, ולכל
פריט מוצג קישור למקורו.

הנתונים קיימים רק למועמדים שכיהנו בכנסת ושקושרו למזהה שלהם בנתוני הכנסת (ראו
[רשימות המועמדים](#רשימות-המועמדים)). ההצבעות במליאה מגיעות עד הכנסת ה-24 בלבד,
כך שלח״כים של הכנסת ה-25 מוצגות הצעות חוק בלי היסטוריית הצבעות.

## חטיבה 2 — מנועי נתונים ו-ML

### ETL

```bash
python3 -m pipeline.run_etl --dry-run   # שליפה וניקוי בלי כתיבה
python3 -m pipeline.run_etl             # ריצה מלאה
```

- **Extract** — מודול לכל מקור: `knesset_api.py` (Knesset OData / data.gov.il),
  `polls_scraper.py` (JSON/CSV או טבלת HTML), `news_rss.py` (פידי RSS בלבד).
  לקוח ה-HTTP המשותף מזדהה בשמו, מכבד `robots.txt`, מגביל קצב ומנסה שוב בהשהיה
  מדורגת.
- **Transform** — נרמול שמות מפלגות (`party_mapping.py`), דה-דופליקציה,
  ולידציה (סכום מנדטים ≈ 120, גודל מדגם סביר). שם מפלגה שלא זוהה **מדווח ואינו
  מנוחש** — מישהו צריך להוסיף alias.
- **Load** — upsert אידמפוטנטי לפי מפתח טבעי. הרצת אותו יום פעמיים לא מכפילה
  שורות. כל ריצה נרשמת ב-`EtlRun` עם ספירות ושגיאות לכל מקור.
- כשל של מקור אחד לא מפיל את השאר; הריצה מסתיימת בסטטוס `partial`.

#### מה שירות הכנסת מכסה בפועל

הקונקטור נכתב מול תשובות שנצפו בפועל מהשירות, לא מול שמות שדות משוערים; את
המבנה אפשר לקרוא מחדש בכל עת דרך `.github/workflows/probe-knesset.yml`. שלוש
עובדות שכדאי להכיר, כולן נמדדו ולא הונחו:

- **הצבעות מגיעות עד הכנסת ה-24 בלבד.** ההצבעה האחרונה שהכנסת מפרסמת ב-OData
  היא מ-13 ביולי 2021; אין ולו הצבעה אחת מהכנסת ה-25. הצינור קורא את התקרה
  מהשירות, מדלג על שליפת ההצבעות כשהיא מעבר לה, ורושם על כך הערה ב-`EtlRun`
  במקום להחזיר היסטוריה ריקה בשקט. ביום שהפרסום יתחדש, ההצבעות ייטענו מעצמן.
- **הצעות חוק כן מכסות את הכנסת ה-25** — הן בשירות אחר (`ParliamentInfo.svc`).
- **השירות חותך כל תשובה ב-100 שורות** ואינו מציין זאת. הקונקטור מדפדף.
- **תאריך פרסום קיים רק להצעות שהפכו לחוק.** להצעות חוק אין תאריך במאגר, ושדה
  "עודכן לאחרונה" אינו תאריך של ההצעה: בהצעות ישנות הוא 29 ביוני 2021, יום הסבת
  הנתונים. לכן הצעה בלי תאריך מוצגת לפי הכנסת והשנה שבשמה ("הכנסת ה-18 · 2012"),
  ולא בתאריך מומצא. לכל מועמד נשמרות 50 ההצעות האחרונות, והסדר נקבע לפי התאריך
  או, בהיעדרו, לפי השנה.

### סקרים אמיתיים

```bash
python3 -m pipeline.run_etl     # מחליף את סקרי ההדגמה בסקרים שפורסמו
```

בישראל אין API ציבורי לסקרים; הם מתפרסמים בכתבות. `wikipedia_polls.py` קורא את
טבלת הסקרים של ויקיפדיה — המקום היחיד שאוסף אותם בצורה מובנית, ברישיון פתוח
ובנתיב ש-`robots.txt` מתיר. **ויקיפדיה היא מנגנון האיסוף, לא המקור המצוטט:**
`sourceUrl` מצביע על הכתבה שהשורה מפנה אליה (מעריב, ערוץ 14, ישראל היום), ורק
כשלציטוט אין קישור הוא נופל חזרה לוויקיפדיה.

הקבלה קפדנית בכוונה. הדף מכיל 58 טבלאות, ורובן אינן סקרי מנדטים — העדפה לראשות
ממשלה, תרחישי קואליציה, מפלגות היפותטיות. טבלה מתקבלת רק אם הכותרת שלה נושאת את
כל ארבעת השדות `Fieldwork date`, `Polling firm`, `Publisher`, `Sample size`, וכל
שורה שאינה נקראת נספרת ומדווחת. **לפספס סקר אפשר לתקן; להמציא סקר לא.**

שני דברים שהפרסר מטפל בהם במפורש, כי שגיאה בהם נראית כמו נתון תקין:

- מפלגה מתחת לאחוז החסימה מודפסת כ-`(0.7%)` במקום מנדטים. זה נקרא כ**אפס
  מנדטים**, לא כ-0.7.
- עמודות סיכום (`Gov.`, `Opposition`, גושים) נפסלות. עמודת `Gov.` שמחזיקה כ-50
  מנדטי קואליציה נראית בדיוק כמו מפלגה, ופסלה בעבר 126 סקרים תקינים.

**טעות הדגימה מחושבת** מגודל המדגם (1.96·√(0.25/n)) כי הטבלה אינה מפרסמת אותה.
זהו ערך נגזר, לא הנתון של בית הסקרים.

**הזנה ידנית גוברת.** `data/sources/manual_polls.csv` (ראו את קובץ ה-`.example`)
מאפשר לתקן שורה שגויה או להוסיף סקר שטרם הגיע לוויקיפדיה. שורה ידנית מחליפה את
האוטומטית לאותו בית סקרים ותאריך.

**סקרי ההדגמה נמחקים** ברגע שנטענו סקרים אמיתיים — האתר אינו מסנן לפי מקור,
ולכן השארת שניהם הייתה ממצעת סקרים מומצאים יחד עם מפורסמים. המחיקה מותנית
בהצלחת הטעינה, כך שריצה כושלת לא מרוקנת את האתר.

### רשימות המועמדים

```bash
python3 -m pipeline.load_candidates --dry-run          # כל הרשימות, בלי כתיבה
python3 -m pipeline.load_candidates --party likud      # רשימה אחת
```

הרשימות הן אלה שאישרה ועדת הבחירות המרכזית לכנסת ה-26. הן נקראות מעותקי ה-PDF
שהמכון הישראלי לדמוקרטיה מארח לכל רשימה (הכתובות ב-`data/sources/candidate_lists.json`),
וכל מועמד נושא את הקובץ כמקור. נטענים רק 35 המקומות הראשונים בכל רשימה, כי מעבר
להם המקומות אינם ריאליים; הרשימה כולה עדיין נקראת ונבדקת, כך שקובץ פגום נתפס גם
כשהפגם מתחת לחיתוך. טעינה מחליפה את המועמדים של אותה מפלגה בלבד.

קובצי ה-PDF הם הדפסת דפדפן של רשת בשלוש עמודות, ומכאן רוב העבודה של הפרסר
(`pipeline/etl/extract/candidate_lists.py`): הטקסט מגיע בסדר חזותי (עברית וספרות
הפוכות), עמודות לעיתים צפופות, ושני רכיבים של gov.il — תג "עוזר ה-AI הממשלתי"
והכותרת התחתונה — נוחתים בתוך שמות. **רשימה שלא נקראת במלואה אינה נטענת כלל:**
מקום חסר, שם ריק או אות לטינית בשם פוסלים את הרשימה כולה. ברשימות משותפות נשמרת
לכל מועמד המפלגה שהגישה אותו.

**סדר השם.** הוועדה מדפיסה שם משפחה קודם, בלי לסמן היכן הוא נגמר. שם בן שתי מילים
מתהפך; שם ארוך יותר מסודר רק לפי `data/sources/candidate_names.json`, שנכתב ביד
(מפיצול השם במאגר הכנסת לח״כים, ממבנה השם בשאר המקרים). שם בלי רשומה נשאר בסדר
הרשמי ומדווח בטעינה. ניסיון לחלק שמות אוטומטית לפי מילון שנלמד מהרשימות נזנח:
הוא הפיק בביטחון שמות שגויים לאנשים אמיתיים. אותו קובץ מתקן גם את המקרים הבודדים
שבהם ההדפסה עצמה חורגת מהמוסכמה (שם פרטי קודם, שגיאת כתיב).

**קישור לנתוני הכנסת.** `data/sources/candidate_knesset_links.json` מקשר מועמדים
שכיהנו בכנסת למזהה שלהם ב-`KNS_Person`. כל קישור נבדק ביד: שם זהה לח״כ אחר — חבר
מפלגה אחרת, או מי שכיהן לפני עשורים בלי קשר לרשימה — אינו מקושר, כי קישור שגוי
מייחס למועמד אמיתי הצעות חוק והצבעות של אדם אחר. בלי קישור ה-ETL אינו טוען דבר
למועמד, וזו ברירת המחדל הבטוחה.

### מנוע המלצות למצביע

עמדת כל מפלגה נקבעת **שאלה אחר שאלה**, מול כל אחד מ-25 ההיגדים. המקור הוא תיוג
ידני של המצע המפורסם, ולמפלגה שאין לה מצע — של הצעות החוק של חבריה (המחברות
`research/03` ו-`research/05`). לכל עמדה יש כיוון (מסכימה עם ההיגד, מתנגדת, או
עוסקת בו בלי כיוון) ורמת ודאות, ונשמרים לצידה הקטע או הצעת החוק שעליהם היא נשענת:

- `sure` ‏±1, ‏`partial` ‏±0.5, ‏`unclear` ‏0.
- שאלה שהמפלגה לא מכוסה בה **חסרה** — זה לא 0. ‏0 אומר "לא נוקטת עמדה"; חוסר
  אומר "אין לנו מידע".
- למפלגה שיש לה גם מצע וגם הצעות חוק, המצע גובר בכל שאלה, והצעות החוק משלימות
  רק את מה שהוא לא מכסה.
- שכבה שלישית, **הצהרות** של ראש המפלגה (`research/statement_coverage_*.csv`),
  ממלאת רק שאלות ששני המקורות האחרים לא מכסים. רק ציטוט ישיר, עם הדובר, התאריך
  וקישור; עד כה לרע"מ, לכחול לבן ולרשימה המשותפת, שיש עליהן הכי מעט מידע.

`python3 -m pipeline.ml.positions` מאחד את התיוג לקובץ
`data/positions/party_positions.json` (נשמר ב-git, כי הקישורים לקטעי המצע נבנים
מטקסטי המצעים שמחוץ ל-git), ו-`pipeline.ml.build_vectors` טוען אותו ל-`PartyVector`.

בזמן ריצה `/api/match` (`web/lib/cosine.ts`) משווה את התשובות לעמדות:

- **קוסינוס מוסווה וממושקל** — רק על שאלות שגם המשתמש ענה עליהן וגם ידועה בהן
  עמדת המפלגה. התשובה והעמדה נמדדות מול אותו היגד, ולכן אין צורך בהיפוך כיוון.
- **כיווץ** — הציון מוכפל ב-`n/(n+16)`, כש-`n` הוא מספר השאלות המשותפות. בלי זה,
  מפלגה שידוע עליה מעט מגיעה בקלות ל-100% (על שאלה אחת הקוסינוס הוא רק ‎+1 או
  ‏‎−1). ה-16 נבחר בסימולציה של `research/08_bias_diagnostics.ipynb`: מול תשובות אקראיות כמעט
  אין קשר בין כמות העמדות של מפלגה לסיכוי שלה לצאת ראשונה, ו-81% מהמצביעים
  המדומים שחושבים כמו מפלגה מקבלים אותה ראשונה.
- **הסבר** — לכל מפלגה: על כמה שאלות הציון נשען, ושלוש השאלות שקירבו ושלוש
  שהרחיקו, כל אחת עם קישור למקור.

**מגבלה ידועה:** לרשימה המשותפת, לרע"מ ולכחול לבן יש 6–7 עמדות בלבד. הרשימה
המשותפת יוצאת ראשונה אצל כ-12% מהמשיבים האקראיים, מול כ-7% הוגנים, בכל ערך של
הכיווץ — זה נובע מהעמדות עצמן, לא ממספרן. עמדות שמוסיפים למפלגה דלילה יכולות
דווקא להגדיל את ההטיה כל עוד מספרן קרוב לקבוע הכיווץ, ולכן אחרי כל הוספה מריצים
שוב את מחברת 08.

**התשובות אינן נשמרות בשום מקום** — הן חיות ב-localStorage של הדפדפן, נשלחות
לחישוב וחוזרות. אין רשומת משתמש ואין מדידה על המסלול הזה.

## מה אמיתי ומה לא

| נתון | מצב |
|---|---|
| שמות מפלגות, יושבי ראש, גושים, תמצית מצע | עובדות ציבוריות, לכל שורה מקור |
| מיקום המפלגות על הצירים (`position`) | **אפיון עריכתי** לצורך אתחול מנוע ההתאמה |
| סקרים | **סינתטיים עד להרצת ה-ETL.** נוצרים מנתיב מגמה ומיוחסים לבתי סקרים בדויים בעליל. `python3 -m pipeline.run_etl` מחליף אותם בסקרים שפורסמו — ראו [סקרים אמיתיים](#סקרים-אמיתיים) |
| מועמדים | **מהרשימות הרשמיות** שאישרה ועדת הבחירות המרכזית, 35 הראשונים בכל רשימה — ראו [רשימות המועמדים](#רשימות-המועמדים) |
| סדר השם הפרטי ושם המשפחה | **החלטה עריכתית** לשמות של שלוש מילים ומעלה, מתועדת ב-`candidate_names.json` |

מועמדים מוצגים רק מהרשימות הרשמיות — לא שמות משוערים ולא נתוני הדגמה. ייחוס
הצבעות או התבטאויות שלא נאמרו לפוליטיקאים אמיתיים אינו מקובל גם בנתוני דמה. מפלגה
שאין לה רשימה טעונה מציגה "הרשימה טרם פורסמה".

לפיתוח, על מסד ריק, אפשר לייצר מועמדים בדיוניים (מסומנים בשמם כ"מועמד/ת לדוגמה"):

```bash
python3 -m pipeline.seed --candidates-per-party 6
```

כל שורה נושאת `provenance` (`seed` או `etl`), וכל עוד קיימת שורת `seed` אחת
האתר מציג באנר "נתוני הדגמה" בראש כל עמוד.

### כללים שנאכפים בקוד

- **אין נתון ללא מקור.** `sourceUrl` ו-`sourceName` הם שדות חובה, ו-`require_source`
  ב-`pipeline/etl/transform/normalize.py` דוחה כל רשומה בלעדיהם. אין נתיב כתיבה
  אחר לטבלאות המתועדות.
- **ניטרליות בתצוגה.** סדר המפלגות נקבע לפי ממוצע הסקרים או לפי א״ב — לא ידנית.
- **הצהרה קבועה** שממוצע סקרים אינו תחזית תוצאות, לצד טעות הדגימה של כל סקר.

## הפעלת מקורות אמיתיים

שום אתר אינו נגרד כברירת מחדל. איזה מקורות מותר לשאוב, ובאילו תנאים, היא החלטה
של מי שמפעיל את המערכת — ולכן היא בקובץ קונפיגורציה ולא בקוד:

```bash
cp data/sources/polls.example.json      data/sources/polls.json
cp data/sources/news_feeds.example.json data/sources/news_feeds.json
# ערכו את הקבצים, סמנו "enabled": true במקורות שמותר לכם להשתמש בהם
python3 -m pipeline.run_etl --dry-run
```

בדקו את תנאי השימוש של כל אתר לפני הפעלתו. לקוח ה-HTTP מסרב לכל כתובת ש-`robots.txt`
אוסר. פידי חדשות נקראים כ-RSS בלבד, לעולם לא כדפי כתבה, והכותרות נשמרות כלשונן
עם קישור למקור.

ה-ETL טוען הצבעות והצעות חוק רק למועמדים שמקושרים למזהה ח״כ
(`Candidate.knessetMemberId`), כדי שלא ייווצרו רשומות יתומות. הקישור מוגדר
ב-`data/sources/candidate_knesset_links.json` — ראו [רשימות המועמדים](#רשימות-המועמדים).

## צבעים ונגישות

צבעי המפלגות בגרפים אינם צבעי המותג שלהן אלא פלטה קטגורית שנבחרה לקריאוּת.

**הפלטה אינה עוברת את בדיקת הנגישות, ואי אפשר שתעבור.** עם 14 רשימות, ההפרדה
הטובה ביותר שהצלחנו להגיע אליה בין הזוג הקרוב ביותר היא ΔE של 2.1, כשהרף הנדרש
הוא 6–8 בעיוורון צבעים ו-15 בראייה תקינה. זו מגבלה מובנית: פלטה קטגורית נשברת
סביב שמונה צבעים, ו-14 קטגוריות פשוט אינן ניתנות להפרדה בצבע בלבד. מדידה
במאמת של מיומנות ה-dataviz, `--pairs all`, בבהיר ובכהה.

**המסקנה המעשית: צבע לעולם אינו הקידוד היחיד.** הגרף מציג עד שש סדרות בו-זמנית
והמשתמש בוחר מי מוצג; לכל סדרה יש תווית שם ומקרא; ולכל גרף יש תצוגת טבלה
חלופית. מי שאינו מבחין בין שני גוונים יכול לקרוא כל מספר באתר בלעדיהם.

מה שכן תוקן: שני זוגות שהיו בפועל אותו צבע — עוצמה יהודית מול יהדות התורה
(ΔE 0.8 בעיוורון אדום-ירוק) ועמך ישראל מול ש״ס (ΔE 2.2) — מוקמו מחדש. אין
ייצור אוטומטי של גוונים חדשים לסדרה נוספת.

## פיתוח

```bash
npm run test --prefix web      # 39 בדיקות יחידה ללוגיקה המספרית
npm run typecheck --prefix web
npm run lint --prefix web
npm run build --prefix web
```

הבדיקות מכסות את שלושת האלגוריתמים שכל השאר תלוי בהם: הממוצע הנע (חלון, משקלים,
ימים ללא סקרים), הקצאת המנדטים (אחוז חסימה, סכום 120 מדויק, תיקו דטרמיניסטי,
הסכמי עודפים) וההתאמה (קוסינוס מוסווה, כיווץ, משקלי חשיבות, הסבר עם מקורות).

שני workflows, בהפרדה מכוונת:

- **`.github/workflows/checks.yml`** — רץ בכל דחיפה ובכל pull request: typecheck,
  בדיקות, lint ו-build, ולצידם הרצה מלאה של הצינור מול מסד נקי — כולל בדיקה
  שה-seed באמת אידמפוטנטי ושמסלול ה-fallback של הסקירה עובד בלי מפתח API.
- **`.github/workflows/daily.yml`** — רץ יומית ב-04:15 UTC וגם ידנית, ומריץ את
  הצינור מול המקורות החיים.

ההפרדה חשובה: אתר חדשות שמשנה את ה-HTML שלו לא אמור להיראות כמו חבילת בדיקות
שנשברה.
